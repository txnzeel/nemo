# Learning guide — Evidence-first web product

## Meaning and business purpose
Next.js provides the browser workspace over the FastAPI boundary. A Decision Case brings
a question, observations, competing explanations and next investigation together.
The business purpose is accountable review, not maximizing the number of charts.

## Example and formula
A payment-stage hypothesis can show observed conversion and device payment rates next
to an explicit causal limitation. Displayed percent = round(numerator / denominator ×
100, two decimal places). BigInt arithmetic rounds only the display; exact source ratios
remain inspectable. Merchandise rupees = integer paise / 100 with two exact digits.

## Data and implementation
The local Next server uses a read-only API token kept out of client bundles. An allowlisted
proxy reads registered datasets; it cannot submit SQL, paths or ledger writes. Integer JSON
tokens become decimal strings using Node 24's JSON reviver source before Number rounding.
The browser renders backend findings, readiness and provenance. React escapes source text.
The interface supplies loading, error, empty and unsupported-evidence states.

## Failure modes and trade-offs
An HTTP response is not proof of valid evidence. Unknown remains unknown, and unsupported
diagnoses remain withheld. Source labels are declarations. A local workstation UI is not
multi-tenant authentication. Cross-origin/host checks restrict browser access; production
deployment needs an independent identity and threat review. A read-only first web surface
keeps action execution in the existing audited workflow.

## Interview explanation
“I put the Decision Case at the center: what changed, how trustworthy it is, what could
explain it and what to investigate. I reused backend semantics, preserved exact money and
kept credentials server-side. The browser cannot upgrade a hypothesis into a causal claim.”
